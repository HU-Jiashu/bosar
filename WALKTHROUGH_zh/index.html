    Bosar 上手手册：从全新克隆到市中心的形变图与损毁代理图¶

    用的是安装版？ 这份手册是在源码检出上写的。用到源码树的步骤（git clone、pip install -e、scripts/...、pytest）需要源码；源码不公开，只按作者的源码许可提供（见 Licensing）。用安装包的读者从 Install 和第 50 步（安装版）开始；其余各步的 bosar 命令就是安装版的命令。

    适用版本：v0.1.0-alpha.1（第 1 阶段结束）。这份手册回答"软件现在做到哪一步"： 每一条命令都在写手册时逐字运行过，完整输出在 发布说明。没有图形界面， 所有操作都在 PowerShell 里完成。

    目标：在 Indianapolis 市中心 7.2 × 10.8 km 的裁剪区上，从 SNAP 导出的 GAMMA/StaMPS 栈出发， 得到地理编码的视线向形变图 geo_disp、相干变化的损毁代理图 geo_dpm、幅度对数比与 RGB 合成图， 再把它们裁到高速公路两侧 500 m 的范围导出成 COG + GeoPackage。整个过程在 CPU 上约 8 分钟， 其中大部分是第 2 步的 pip 安装；处理本身不到 2 分钟。

    第 0 步：按你的机器修改这三个变量（唯一需要改的地方）¶

    $DATA = "<data-root>"                  # 只读数据池（本手册只读取，不写入）
$MAIN = "<repo>"       # 已经编译过 SNAPHU 的主工作目录
$WORK = "<repo>\data\walkthrough_bosar"   # 放新克隆的位置

    $DATA 下用到的文件：GAMMA 栈 01_Preprocessed\01_IW2\、原始 zip 00_RawData\S1A_IW_SLC__1SDV_20240821T..._E05B.zip（只读几何注释，不解压）、高速公路线 04_GIS\indianapolis_highways.geojson、GACOS 文件夹 05_Auxiliary\00_GACOS\。

    第 1 步：克隆代码¶

    New-Item -ItemType Directory -Force $WORK | Out-Null
Set-Location $WORK
git -c safe.directory=* clone --quiet $MAIN bosar_walk
Set-Location bosar_walk
git -c safe.directory=* log --oneline -1

    克隆来自第 0 步的主工作副本（$MAIN）；GitHub 上的公开仓库只放文档和安装包，不放源码。拿到源码仓库地址的读者把它换到 $MAIN 的位置。在不记录文件所有者的 磁盘上，git 会对新克隆报 "dubious ownership"（退出码 128）；上面这条命令只对这一次放行，不改你的全局配置。 想长期放行，可以自己执行 git config --global --add safe.directory <克隆目录>。

    第 2 步：建立 Python 环境¶

    python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --quiet -e ".[dev,unwrap,viz]"
python --version
    • unwrap 装 scikit-image（没有 SNAPHU 时的解缠后备），viz 装 matplotlib（快视图）。
    • 有 NVIDIA 显卡时再装 python -m pip install -e ".[gpu]"，软件自动用 CuPy；本手册不装， 全部在 CPU 上跑（preflight 会提示 W401，属正常）。

    第 3 步：开发环境变量¶

    . .\scripts\dev_env.ps1

    把 ruff / pytest / CuPy 的缓存都放进仓库内的 .cache\，并提醒：同一时间只应有一个使用 GPU 的进程（跑流水线时不要同时跑完整测试）。

    第 4 步：自检 preflight¶

    bosar version
bosar preflight

    逐项检查 Python、依赖、GPU、磁盘、SNAPHU 等；OK 通过、WARN 可以继续、FAIL 会阻止运行。 全新克隆里还没有 SNAPHU 可执行文件，P401 显示 WARN（W501：会退回 scikit-image）。

    第 5 步：放入 SNAPHU¶

    New-Item -ItemType Directory -Force packaging\bin\win-x64 | Out-Null
Copy-Item "$MAIN\packaging\bin\win-x64\snaphu.exe" packaging\bin\win-x64\
bosar preflight | Select-String "P401"

    SNAPHU 2.0.6 由 packaging\snaphu\build.ps1 用 MinGW-w64 编译；它和 author 在 WSL 里跑的 SNAPHU 对同样输入给出逐像素相同的结果。 二进制文件不进 git（许可证与平台原因），所以新克隆要从主目录复制或自己编译。复制后 P401 为 OK。

    第 6 步：新建项目¶

    bosar project new walk --name walk_demo --storage-mode full

    项目就是一个文件夹：project.json（步骤、参数、产品清单）、products\、logs\、scratch\。 full 保留全部中间产品（便于查看）；默认的 minimal 会在链结束后删除可再生的中间文件。

    第 7 步：从全栈裁出市中心¶

    bosar data crop "$DATA\01_Preprocessed\01_IW2" --window 7904,8672,2590,5662 --dates 20240704,20240821,20240902,20240914,20250723 --annotation "$DATA\00_RawData\S1A_IW_SLC__1SDV_20240821T234025_20240821T234052_055318_06BEBA_E05B.zip" --out data\indy_downtown_crop

    从 12239 × 25925 的 IW2 栈里按窗口读出 768 × 3072 像素、5 个日期（只读，窗口读取，不载入整景）， 写成本仓库 data\ 下的 GeoTIFF + crop.json。--annotation 直接从原始 zip 里读 SAFE 注释， 把 SNAP 导出里的名义几何（距离向 2 m、地球半径小 11.5 km）改成真实值（2.33 m 等）， crop.json 里记 I201。

    第 8 步：导入裁剪区和全栈¶

    bosar data import walk data\indy_downtown_crop
bosar data import walk "$DATA\01_Preprocessed\01_IW2" --annotation "$DATA\00_RawData\S1A_IW_SLC__1SDV_20240821T234025_20240821T234052_055318_06BEBA_E05B.zip"
bosar project info walk

    导入只登记元数据（日期、几何、基线、足迹），原始数据留在原地。全栈 29 景，20240821_20240704 的 B⊥ 从名义几何的 223.8 m 校正为 213.9 m（SNAP 自己给 216.1 m）。项目里有两个栈，后面的流水线 用 --stack 指明。

    第 9 步：DInSAR 流水线 → geo_disp¶

    bosar pipeline dinsar walk --stack crop_indy_downtown_crop --all-pairs --looks 2,10 --backend snaphu --geocode-coh

    每一对干涉图依次运行：ifg_import（引用栈里的差分干涉图）→ multilook（2 × 10 视，28 × 23 m） → coherence（DInSAR v0.1.0 起默认用 slc-box 配方：全分辨率 5 × 5 窗口，再在 2 × 10 块里平均， 与 MintPy 的相干一致；--recipe looks 是标准估计，每个多视块 20 个样本。CCD 则默认 looks，见第 11 步）→ goldstein（滤波） → unwrap（SNAPHU， 单块）→ geocode_unw → displacement（d = −λφ/4π，米，朝向卫星为正，参考点为 0）→ geocode_disp → geocode_coh。屏幕上每行一步，最后一行是运行日志的位置。 四对共 36 步，CPU 上约 25 秒（结果与 GPU 一致到 1e-6）。

    第 10 步：看快视图¶

    Get-ChildItem walk\products\figure -Name | Select-Object -First 12
    • *_coherence.png：相干（黑 0 → 白 1），河道、植被暗，建筑、道路亮。
    • *_unwrapped.png：解缠相位（弧度，红蓝对称）。
    • *_displacement.png：视线向形变（毫米，红 = 朝向卫星，蓝 = 远离卫星，色标取 2–98 % 对称）， 12–48 天的短对上主要是大气（厘米级），不是地面沉降。
    • geo_* 产品（walk\products\geo_disp\ 等）是 EPSG:4326 的 GeoTIFF，可直接拖进 QGIS。

    第 11 步：相干变化检测 → geo_dpm¶

    bosar pipeline ccd walk --pre 20240821_20240902 20240821_20240914 --co 20240821_20240704
bosar pipeline ccd walk --pre 20240821_20240902 20240821_20240914 --co 20240821_20250723

    --pre 是事件前的两对（夏季，12/24 天），--co 是"事件"对。没有真实的破坏事件，所以： 第一条是空检验（同一季节的另一对）；第二条是季节伪事件（336 天，跨过冬季）。实测结果 （用的是标准估计 looks，详见发布说明）：按分位阈值 2 % 超阈、去斑点后约 0.36 % 留在图上；但两种情况的图 都集中在相干的城区目标上，而不是植被——在 C 波段 12/24 天的夏季对里，农田和林地在事件前就已经 失相干，没有可失去的相干，所以审查预期的像土地覆盖图这种失效方式在这批数据上不会出现。空检验也 不是纯噪声：48 天的事件对本身比 12/24 天的事件前对更失相干，固定阈值 z ≥ 3 会标出约 5 %。产品：ccd_delta（相干下降量）、ccd_z（按事件前各对之间的离散度标准化，正 = 下降）、 dpm（1 = 显著下降，0 = 无，255 = 事件前相干 < 0.3 被屏蔽），以及地理编码的 geo_ccd、geo_dpm。 人工注入的 200 m 损毁块能被检出（测试 tests/test_ccd.py，looks 下精度与召回 ≥ 0.9）。 两种相干配方的取舍：slc-box 方位向 5 行的窗口大于 2 视，相邻多视像素共用样本， ccd_z 在空间上相关（空检验的 Moran's I 约 0.37，looks 下 < 0.1），损毁块边缘会多标出一圈像素（召回 仍为 1，精度约 0.72）——偏差小但边界发虚；looks 像素彼此独立、边界清晰，低相干处偏差略大。做损毁 制图时定位比偏差更要紧，所以 pipeline ccd 和界面的 CCD 工作流默认 looks（DInSAR 仍默认 slc-box）。如果 CCD 读到的是 slc-box 相干，日志里会记一条 W106 说明；想用它就显式加 --recipe slc-box（新算的相干步骤建议加 --tag，两套结果并存）。

    第 12 步：幅度变化（对数比与 RGB）¶

    bosar run walk amplitude --step-id amplitude_crop --stack crop_indy_downtown_crop --looks 2,10
bosar run walk log_ratio --step-id log_ratio_20240821_20250723 --requires amplitude_crop --pre 20240821 --post 20250723
bosar run walk rgb_composite --step-id rgb_20240821_20250723 --requires amplitude_crop --pre 20240821 --post 20250723
bosar run walk geocode --step-id geocode_log_ratio_20240821_20250723 --requires amplitude_crop --requires log_ratio_20240821_20250723 --source log_ratio

    GAMMA 栈没有辐射定标，所以幅度变化是相对的：每个日期先在"稳定散射体"（幅度离散度最低的 95 % 像素）上归一化，再算 10·log10(I_后/I_前)（正 = 变亮）。RGB 合成里红 = 事前、绿蓝 = 事后： 红色是变暗，青色是变亮，灰色是不变。定标查找表（σ⁰）已经能直接从原始 zip 读出（33 个 zip 全部可读）， 在 v0.2.0 的原生 SAFE 流程里使用。

    第 13 步：导出（裁到高速公路两侧 500 m）¶

    bosar export walk all --aoi "$DATA\04_GIS\indianapolis_highways.geojson" --buffer-m 500 --out walk\export
Get-Content walk\export\README.txt -TotalCount 25

    每个地理编码产品写成一个云优化 GeoTIFF（COG），高速公路 500 m 以外设为无数据；矢量（产品范围、 参考点、AOI、栈足迹）写进一个 GeoPackage；README.txt 和 export.json 写明每个文件的单位、 符号约定、参考点、日期对和运行编号。

    第 14 步：日志在哪里、怎么看¶

    bosar logs walk --tail 3
Get-ChildItem walk\logs -Name | Select-Object -Last 3

    每次运行一个 logs\run_*.jsonl（每行一条 JSON，UTC 时间精确到微秒，含参数、输入、输出、用时、 峰值内存），旁边是给人看的 .log 和 Markdown 报告 .md。bosar logs walk --failure 显示 最近一次失败的原因和提示。

    第 15 步：GACOS 申请卡与已有文件的校验¶

    bosar aux gacos-request walk --stack gamma_01_IW2
bosar aux gacos-check walk --stack gamma_01_IW2 --dir "$DATA\05_Auxiliary\00_GACOS"

    第 23 步：派生小基线干涉图、公共参考点、批量解缠¶

    bosar sbas prep walk --stack crop_indy_downtown_crop --network crop --looks 2,10 --backend snaphu --workers 3 --nproc 2 --tag sbas

    步骤 id 带网络名（coherence_<对>_crop_sbas），同一项目里两个栈的网络互不干扰。四个可续跑的阶段：prepare——每对 ifg_derive → multilook → coherence（ifg_derive 用星形栈 diff(ref,i)、diff(ref,j) 与参考影像功率算出平地化的 (i, j) 对，相干用同一分子和两景 SLC 功率）； reference——所有对里都相干（≥ 0.3）的像元中平均相干最高的那个当公共参考点（写进网络记录）； unwrap——每对 SNAPHU（smooth 代价）、统一参考；closure——见下一步。--workers 3 让三对并行 （子进程，CPU），project.json 的并发写入靠修订号合并。裁剪区 9 对：prepare 约 1 分钟/对， unwrap 1–3 秒/对，参考像元 (20, 167)。

    第 24 步：三元环闭合（B4）¶

    sbas prep 的最后一步就是 closure；也可以单独跑：

    bosar sbas prep walk --stack crop_indy_downtown_crop --network crop --phase closure --looks 2,10 --tag sbas

    每个闭合三角算两样：缠绕相位闭合 arg(c_ij c_jk conj(c_ik))（相位偏差）和解缠相位的整数闭合 round((u_ij + u_jk − u_ik − w)/2π)（解缠错误）；产品 closure/wrapped_rms、closure/integer_count， 摘要里有逐三元环、逐对（含"系统性错误"标记）和只看相干像元的统计。裁剪区 7 个三元环：缠绕闭合 RMS 中位数 0.94 rad（三对都相干的像元 0.43–0.52 rad），整数闭合非零的像元占 9–24 %（相干像元 2–11 %；夏季三元环 20240821-0902-0914 最好，2.2 %）。

    第 25 步：用 SNAP 做预处理（需要装好 ESA SNAP）¶

    bosar preflight --offline
bosar pipeline preprocess walk --engine snap --product "$DATA\00_RawData\S1A_IW_SLC__1SDV_20240821T234025_20240821T234052_055318_06BEBA_E05B.zip" --product "$DATA\00_RawData\S1A_IW_SLC__1SDV_20240902T234025_20240902T234052_055493_06C53E_B90F.zip" --product "$DATA\00_RawData\S1A_IW_SLC__1SDV_20240914T234026_20240914T234052_055668_06CC28_B2FF.zip" --subswath IW2 --aoi-wkt "POLYGON((-86.30 39.65,-86.00 39.65,-86.00 39.90,-86.30 39.90,-86.30 39.65))" --threads 8 --cache-mb 8192 --tag subset

    预检的 P402 报告 SNAP 的 gpt、工具箱和堆内存。命令把 SNAP 当作单独的程序调用（不复制、不导入 SNAP 的代码）：TOPSAR-Split（按 AOI 选 burst）→ Apply-Orbit-File（用第 18 步找到的本地轨道，复制到 walk/snap/userdir）→ Back-Geocoding（外部 DEM = 第 19 步的椭球高拼接，walk/aux/dem）→ ESD → Interferogram（平地 + 地形相位、相干、高程、经纬度）→ Deburst，产品是 BEAM-DIMAP，随后自动导入 （data import --reader dimap --ifg-dim）成栈 snap_subset，第 8 步之后的所有命令都能用它。SNAP 写的每个文件都在 walk/snap/ 和 walk/products/dimap/ 里，~/.snap 一个文件都不动。本机上：栈 90 s、干涉图 344 s、gpt 峰值内存 45 GB（gpt.vmoptions 的 -Xmx132G 允许它这么用）。注意：DEM 只 拼了 AOI 那个框，Back-Geocoding 会把没有高程的像元全部置空，所以子集里只有 AOI 框内有数据。

    第 26 步：相干不够时哪些对、哪些像元会被剔除¶

    SBAS 的结果好不好，主要取决于喂进去的解缠相位靠不靠谱。Bosar 把"剔除"做成明确的规则，每一条都 会在命令输出和 project.json 里留下记录，你可以逐条放宽或收紧：

    层次 规则 在哪里调 记录在哪里
    整对 空对：相干处处为 0（导出里该日期的干涉图或 SLC 全零，导入时报 W206） 不可调 网络记录 empty_pairs
    整对 弱对：相干 ≥ 0.4 的像元不到 5 %；但每个日期保留它向前、向后最好的一条连接 sbas prep --min-coherent-fraction 0.05（0 = 不剔除） weak_pairs、weak_pairs_kept、pair_quality
    整对 不可靠对：它参与的每一个三元环里，相干像元上整数闭合不为 0 的比例都超过 30 %（整景去相干或配准坏掉的日期） unw_correct --pair-max-error 0.3 unw_correct 摘要的 unreliable_pairs
    像元 该对在这个像元的相干低于阈值 pipeline sbas --coh-min 0.3 sbas_invert 摘要 pair_pixels_dropped.coherence
    像元 该像元不在参考点所在的解缠连通分量里 --any-component 关闭此规则 pair_pixels_dropped.component
    像元 闭合改正之后该对所在的三元环仍不闭合 --keep-unclosed 关闭此规则 pair_pixels_dropped.unclosed_triplet

    一个像元至少剩下 2 对才有时间序列（--min-pairs）；只有它的网络把所有日期连成一片、并且时间相干 ≥ 0.7，才进入默认掩膜（产品 ts_mask）。如果整对规则把整个网络断成几段（冬季几对全不可靠时会这样）， sbas_invert 报 W107：各段之间的偏移未知，速度按"同一速率 + 每段一个截距"拟合；想把断口接上， 就多留几条跨越断口的对（sbas network --k 调大、--min-coherent-fraction 调小，或用 sbas_invert --exclude-pairs 自己指定）。网络设计还有两个选项：--sequential-only（只要每个日期 时间上最近的 k 条连接）和 --season-months 5-10（拒绝跨季节的对，顺序连接除外）。

    第 27 步：SBAS 时间序列（pipeline sbas）¶

    bosar pipeline sbas walk --network crop --tag sbas --tropo gacos --gacos-dir <data-root>/05_Auxiliary/00_GACOS

    在第 23 步准备好的网络上依次做：unw_correct（按闭合环改正 2π 解缠错误，Yunjun 等 2019 的相位闭合 法，按"闭合模式"去重后每种模式只解一次）→ sbas_invert（逐像元网络的加权最小二乘 / 最小范数解， Berardino 等 2002；权来自相干和视数；输出 ts_los（每个日期一个波段，单位 m，朝向卫星为正）、 velocity（m/yr）及其标准差、temporal_coherence、n_pairs_used、ts_rank、ts_mask）→ ts_correct（每个日期的 GACOS 斜距延迟，参考到参考点和参考日期；--deramp 再逐日期去一个平面； --tropo era5 用 ERA5 气压层数据，需要 CDS key）→ 地理编码（速度、时间相干、时间序列）。 产品内部一律是米和米/年，界面、CSV 和摘要里才换成毫米。改正方式写进步骤 id（ts_correct_crop_sbas_gacos）， 所以不改正、GACOS、ERA5 的结果可以并存对比。这个 5 景裁剪只有 9 对，结果只用来演示流程；26 景的 裁剪（data/indy_downtown_ts，见发布说明）才有像样的时间序列。

    第 30 步：结果能不能用？——质量判定和数据体检¶

    bosar sbas quality walk --network crop --tag sbas

    每条时间序列链（pipeline sbas、pipeline psds）跑完都会打印一个质量判定： USABLE（可用）/ MARGINAL（勉强，只能在说明的限制内读）/ NOT USABLE（不能当形变解读）。 判定来自实测指标，每条都带警告码、实测值、门槛和具体的补救办法：

    警告码 指标 勉强 不可用
    W108 连通且时间相干达标的像元占比 < 20 % < 2 %
    W109 被剔除的干涉对占比，或整天丢失的日期 > 30 % 或有日期丢失 —
    W107 网络断成几段 是 —
    W110 可用像元的速度离散度 > 4 mm/yr > 10 mm/yr
    W111 改正后仍不闭合的三元环占比 > 15 % —
    W112 速度中位数相对参考点明显偏离（场景斜坡或参考点本身有问题） 是 —
    W113 相邻两期之间出现接近半个波长的跳变的像元占比（并指出从哪天开始） > 3 % —

    bosar sbas quality 还会打印逐日期的数据体检表：每个日期有几对、多少是空的（全零）、多少太弱、 多少被闭合检查判为不可靠、平均相干像元占比。所有对都是空的日期是数据问题（那一景在导出里就是空的， 调参数没用，只能重新配准或剔除）；所有对都失败的日期是那天失相干（雪、雨、落叶）。界面里结果页会在 地图上方用横幅显示同样的判定。

    第 31 步：PS / DS 时间序列（pipeline psds）¶

    bosar pipeline psds walk --stack crop_indy_downtown_crop --strides 2,10 --workers 3 --backend snaphu

    植被多的地方多视 SBAS 留不下多少像元。这条链改用两类散射体：分布式散射体（DS）——在每个像元周围 找统计上同质的邻居（SHP，幅度的 GLRT 检验），在这些邻居上估 N×N 的相干矩阵，再用相位联合（EMI） 一次估出 N 个日期的相位；永久散射体（PS）——幅度离差 D_A ≤ 0.25 的点保留自己的相位。两者合成 一个"混合栈"，再走第 23–27 步同样的解缠、闭合、反演。依次是：slc_flatten（用 Bosar 自己的平地相位 把每景 SLC 去平；同时扫描每个日期，有一条缺失带的日期会被检出并默认剔除，W207）→ psds_link （SHP、相位联合、PS 选择；GPU 上 26 景 768×3072 只要十几秒）→ 每对的干涉图 → 解缠 → 闭合改正 → 反演 → 地理编码 → 质量判定。常用选项：--shp glrt|ks、--method emi|evd、--ps-da 0.25、 --strides 方位,距离（输出网格的抽稀）、--ds-tcoh 0.6（DS 需要的相位联合时间相干；纯噪声在这个栈上 最高只有 0.36）、--keep-partial-dates。5 景的裁剪只用来演示流程（日期太少，相位联合意义不大）； 26 景测试区的结果见发布说明。

    第 32 步：经典 PS-InSAR 作为独立对照（pipeline psi）¶

    bosar pipeline psi walk --stack crop_indy_downtown_crop --name psds --max-arc-m 3000

    按 Ferretti 等 2001 / Kampes 2006 重新实现的经典 PSI，不做相位联合也不做空间解缠：PS 候选点 （D_A）→ Delaunay 三角网的边 → 每条边用周期图同时估高程误差和速率（一次矩阵乘法批量算）→ 从参考点沿 最相干的路径积分 → 由残差估大气相位屏并扣除 → 每个点最终估计。结果是一个 GeoPackage 点图层 （products/psi_points/）：LOS 速度（朝向卫星为正）、高程误差、时间相干和每个日期的位移。验收门槛会 按这个栈的日期数自动抬到"纯噪声的 99 分位"之上（日期少时噪声也能凑出很高的时间相干）。它复用上一步 slc_flatten_psds 的去平栈。

    现在的局限与接下来的工作¶

    • 输入可以是 SNAP 导出的 GAMMA/StaMPS 栈、SNAP 桥接的预处理（第 25 步），或 v0.3.0 起 Bosar 自己的 原生 TOPS 配准（第 35、38–40 步：多年栈、定标、三条带拼接）。
    • 时间序列有三条链：SBAS（第 22–27 步）、PS/DS 混合栈（第 31 步）、经典 PSI（第 32 步）。这片 C 波段 植被区上速度噪声在 2–5 mm/yr 量级，一年的数据读不出毫米级形变；质量判定会明确告诉你这一点。
    • 电离层分频估计接进了时间序列链（第 45 步，可选）；ALOS-1、ENVISAT、ERS 的读取器与条带配准链在 v0.4.0 上了真数据（第 47 步），NISAR 只有合成数据；偏移量追踪与斑点滤波在 v0.3.0；安装包在 v0.4.0。

    第 49 步：形变区的质量判定、连接相干门限、下载的两处保险¶

    bosar pipeline sbas demo_alos --network l --tag ex2 --area deforming --exclude-dates 20100522 --fit huber --no-geocode
bosar sbas quality demo_alos --network l --tag ex2
bosar sbas quality demo_multi --network psds --step ts_correct_psds_era5 --area deforming
bosar pipeline sbas demo_multi --network psds_seq --tag gate --link-coherence-min 0.7 --tropo era5 --no-geocode
bosar fetch dem demo_alos --bbox -99.30,19.15,-98.85,19.60 --timeout-s 120
    • --area stable | deforming | auto：稳定区规则（默认）会把 30 cm/yr 的沉降盆地判成 NOT USABLE——速度离散本身就是形变、相邻日期之间的整周步进也是形变。deforming 模式下 W110 看 速度减去 1 km 平滑场后的残差离散，W113 看相对每个像元拟合直线的周跳，W114 看去趋势后的共模步进， W112 不再报；没有指定参考点时，参考点自动移到速度场"最稳定五分位"里相干邻域最密的格元 （--stable-end max 对应沉降场景，min 对应隆升）。auto 在离散超过稳定区预期 3 倍时自动切到 deforming。墨西哥城 16 景序列由此判定 USABLE，参考点自动落在 Cerro de la Estrella 火山岩上。
    • W117 两级：超过 20 % 像元离群的日期只记录（报告里标 (info)），≥ 35 % 才是 marginal， 两个以上 marginal 日期才降判定；sbas quality 现在按当前阈值重新评判存储的指标，--step 指定要 报告的步骤，--area 换一套规则看同一产品。
    • --link-coherence-min 0.7：PS/DS 产品的可靠掩膜再用相位连接的时间相干把一次关——顺序 连接的栈反演相干恒为 1，必须用这个门限，所以 pipeline psds --method sequential 默认就带 0.7 （--link-coherence-min 0 关掉）。三年栈上门限留下 82.5 % 的像元，判定仍是 marginal，地标速度 与不加门限的产品差 0.15 mm/yr 以内——门限换掉的是"可靠"的定义，不是产品。
    • fetch dem --timeout-s（v0.4.0 起唯一路径）：直接从 Copernicus 公开桶下载缺的 GLO-30 瓦片到 <project>/aux/dem/tiles/ 再拼接；fetch slc 对已有文件先核一次 MD5、以后用尾 哈希（最后 1 MiB）快速核对，不再只看大小。

    第 50 步：安装版——不用源码，从 .exe / .dmg 开始¶

    从 v0.4.0 起 Bosar 有安装程序；下面这些命令在安装版上跑（不是这个开发检出），所以写成普通文本块， check_walkthrough.py 不会执行它们。

    1. 从 Releases 下载：Windows 用 bosar-<版本>-win-x64-setup.exe（按用户安装，不需要管理员；向导里勾上"Add the bosar command line to the user PATH"），macOS 用 bosar-<版本>-mac-arm64.dmg（只有 Apple 芯片版；首次打开 右键 → 打开，或 xattr -dr com.apple.quarantine /Applications/Bosar.app）。
    2. 新开一个终端（PATH 生效），看版本和环境：
    bosar version                      # 带 build id：bosar 0.4.0b0 (build 2026…-win-x64 …)
bosar preflight --offline          # P305 显示构建记录；P401 的 SNAPHU 是 "no CS2 solver (MST init)"
    1. 不要任何数据，先跑一遍演示（合成的一对影像、建项目、导入、DInSAR 全链，约一分钟）：
    bosar demo my_demo                 # 8 步 done；my_demo/project 是一个普通项目，可以在界面里打开
bosar-gui my_demo/project          # 或从开始菜单 / Applications 打开 Bosar
    1. 有 NVIDIA 显卡的机器：GPU 是插件，装一次（约 1.5 GB，从 PyPI 取 CuPy 和 CUDA 12 运行库，不需要 pip）：
    bosar gpu install                  # 或 --no-ctk（系统已有 CUDA 12 工具包时）
bosar preflight --offline          # P202 gpu.plugin ok，P201 gpu.backend 显示显卡

    Apple 芯片的 Mac 没有 CUDA，Bosar 在 CPU（NumPy）上跑。 5. 之后第 1–10 步的流程在安装版上完全一样（bosar project new、bosar data import、 bosar pipeline dinsar …）；PS-InSAR（第 32 步的 pipeline psi）和两景差分也都在里面。安装版 的 SNAPHU 没有 CS2 求解器：解缠用 MST 初始化（0.4.1 起所有地方的默认值，步骤摘要里 init: mst）， 结果是同一个最优化问题从另一个起点出发；需要 MCF 初始化的话用源码检出里的 CS2 构建 （packaging/snaphu/build.ps1）并设 unwrap.init=mcf。 6. 许可证：设置页的"About Bosar"卡片显示许可证行（PolyForm Noncommercial 1.0.0；商业授权联系作者）和 三个文件（Licence… / Notice… / Third-party licences…）；安装目录 _internal/licenses/ 里是同样的文本。
