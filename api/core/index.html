    API — core¶

    Pure NumPy/SciPy kernels on the array module xp (bosar.backends.get_array_module()); the same code runs on CuPy when a CUDA device is present and BOSAR_FORCE_CPU is unset.

    Interferometry¶

    bosar.core.interferogram ¶

    Interferogram formation, power and multilooking — pure xp kernels (ARCHITECTURE §5, §6.3).

    Conventions (core/conventions.py): cpx_ifg = ref * conj(sec), phase = angle(cpx_ifg); a range increase from reference to secondary (motion away from the sensor) gives positive phase. Multilooking averages the complex product or the power over (azimuth, range) look blocks — never wrapped phases. Units: looks and shapes in pixels; the caller carries the spacing. Every kernel runs unchanged on NumPy or CuPy (xp).

    form_interferogram ¶

    form_interferogram(
    cpx_ref: Any, cpx_sec: Any, xp: ModuleType
) -> Any

    cpx_ref * conj(cpx_sec) as complex64 (the binding sign convention).

    Units: complex amplitudes in; the phase of the result is radians.

    power ¶

    power(cpx: Any, xp: ModuleType) -> Any

    |z|² as float32 (the SLC power an amplitude product or a coherence denominator needs).

    Units: the SLC amplitude squared (|z|^2), float32.

    multilook_shape ¶

    multilook_shape(
    shape: tuple[int, int], looks: tuple[int, int]
) -> tuple[int, int]

    Output shape of :func:multilook: (rows // la, cols // lr) (ragged edge dropped).

    Units: pixels.

    multilook ¶

    multilook(
    block: Any,
    looks: tuple[int, int],
    xp: ModuleType,
    *,
    reduce: str = "mean",
) -> Any

    Block-average block over looks = (azimuth, range) pixels.

    reduce="mean": complex input is averaged coherently (complex64 out), real input as float32 with NaNs ignored inside a block; reduce="power": |z|² (or the real values) averaged → float32. A ragged edge that does not fill a whole block is dropped (:func:multilook_shape).

    Units: looks and shapes in pixels; values keep the input's units (power = |z|^2).

    fringe_frequency ¶

    fringe_frequency(
    cpx_ifg: Any,
    xp: ModuleType,
    *,
    looks: tuple[int, int] = (2, 2),
    pad_to: int = 1024,
) -> tuple[float, float, float]

    Dominant fringe frequency (f_azimuth, f_range, peak_share) of an interferogram block.

    The block is multilooked by looks (complex sum), reduced to unit phasors, zero-padded to at least pad_to per axis and Fourier transformed; the frequencies of the power peak are returned in cycles per full-resolution pixel (signed: exp(+j 2 pi f x)), with the share of the spectral power in that bin. A mean of pixel-to-pixel phasors is NOT used: on real SLC pairs it is dominated by pixel-scale phase structure.

    Units: frequencies in cycles per pixel of the input grid; peak share dimensionless.

    bosar.core.coherence ¶

    Window coherence estimator (ARCHITECTURE §6.4) — pure xp, one implementation for CPU/GPU.

    γ = |Σ ref·conj(sec)| / sqrt(Σ|ref|² · Σ|sec|²) over an (azimuth, range) window, computed with uniform_filter on the real part, the imaginary part and the two powers. The numerator is the (flattened) interferogram: on the SNAP export it is the .diff, the denominators the two rslc powers, all on the same grid (full resolution or multilooked). Output float32 in [0, 1].

    Two named recipes:

    • looks: the standard estimator over the multilook block — the multilooked interferogram divided by the square root of the product of the two block-mean powers, i.e. coherence(ifg_ml, pow_ml_ref, pow_ml_sec, window=(1, 1)); looks_az × looks_rg samples per value. An extra box on the looked grid (coh_smooth) is the same call with window=(a, b).
    • slc-box (the Step default since v0.1.0): the author's compute_coherence (01_Projects/00_PhD_Prelim_Exam/00_Code/05_utils/gamma_utils.py): a box (5 × 5) uniform_filter on ref·conj(sec) and the two powers at full resolution (mode="reflect"), then the block mean of that coherence over the looks (his snaphu_batch_unwrap.py multilooks the 5 × 5 coherence before writing MintPy's .cor). About 25 samples per value whatever the looks.

    halo_for_window(window: tuple[int, int]) -> tuple[int, int]

    Units: pixels.

    coherence ¶

    coherence(
    cpx_ifg: Any,
    pow_ref: Any,
    pow_sec: Any,
    window: tuple[int, int],
    xp: ModuleType,

    ndi: ModuleType | None = None,

    All three inputs share one grid; mode="reflect" at the array edge, so callers tile with :func:halo_for_window. Pixels whose denominator is 0 (nodata margins) get coherence 0.

    Units: dimensionless coherence in [0, 1]; window in pixels; powers = |z|^2.

    expected_coherence_magnitude ¶

    expected_coherence_magnitude(
    gamma: float, looks: int

    First-order expectation of the estimator for true coherence gamma and looks independent samples: sqrt(γ² + (1 − γ²) / L) (the bias the synthetic tests assert).

    Units: dimensionless (coherence), looks = number of samples.

    bosar.core.filtering ¶

    Goldstein–Werner adaptive phase filter (ARCHITECTURE §6.5) — pure xp, batched FFTs.

    Goldstein & Werner (1998): every patch × patch block of the complex interferogram is Fourier-transformed, its spectrum is multiplied by the smoothed spectral magnitude raised to alpha (|S|^α, α ∈ [0, 1]) and transformed back; overlapping patches (50 %) are blended with a 2-D Hann window. The coherence-adaptive variant (Baran et al. 2003) uses α = 1 − mean coherence of the patch. Output: complex64 of the input shape; the phase is the filtered phase, the magnitude is scaled by the spectral weight (use the phase or normalise).

    halo_for_patch ¶

    halo_for_patch(patch: int) -> tuple[int, int]

    Rows/cols a tile must be grown by so the blended result is exact inside the tile.

    Units: pixels.

    goldstein ¶

    goldstein(
    cpx_ifg: Any,
    xp: ModuleType,
    *,
    alpha: float = 0.5,
    patch: int = 64,
    step: int | None = None,
    smooth: int = 3,
    coherence: Any | None = None,
    adaptive: bool = False,
    fft: ModuleType | None = None,
    ndi: ModuleType | None = None,
) -> Any

    Filter a complex interferogram block; returns complex64 of the same shape.

    patch pixels square, step (default patch // 2 = 50 % overlap), smooth = side of the box that smooths the spectral magnitude (odd, 1 disables), alpha the exponent. With adaptive=True and a coherence array of the same shape, each patch uses α = clip(1 − mean(coherence), 0, 1) instead of alpha. NaN/zero pixels contribute zero power (a nodata margin is not filtered into its neighbours' phase more than a zero).

    Units: complex interferogram in/out (phase in radians); patch, step, smooth in pixels.

    phase_consistency(

    |mean(z)| / mean(|z|) over window — the spatial phase consistency of a single interferogram in [0, 1] (rises when a filter removes phase noise). float32.

    Units: dimensionless [0, 1]; window in pixels.

    bosar.core.flatten ¶

    Simulated flat-earth + topographic phase from orbits and a DEM.

    For a coregistered pair on the reference grid, the raw interferogram S_a · conj(S_b) carries the geometric phase 4π (r_b − r_a) / λ (SLC phase −4π r / λ, core/conventions.py), where r_a, r_b are the zero-Doppler slant ranges of the ground point seen from the two orbits. Removing it (· exp(−j φ_sim)) gives the flattened, topography-corrected interferogram - Bosar's own version of the .diff of an export, built from the precise orbits, the v0.2.0 geometry kernels and the ellipsoidal heights in radar coordinates.

    The range difference is smooth in the image and nearly linear in the target height, so it is evaluated exactly (rdr2geo on the grid orbit, geo2rdr on the other orbits) on a coarse lattice at two heights and expanded per pixel as

    Δr(row, col, h) = Δr₀(row, col) + s(row, col) · (h − h₀)

    with bilinear interpolation of Δr₀ and the height sensitivity s (the per-pixel, range-dependent height-to-phase factor - never a scene constant). Everything is float64 until the final phasor: Δr reaches hundreds of metres and the phase needs sub-millimetre precision.

    RangeModel dataclass ¶

    RangeModel(
    rows: ndarray,
    cols: ndarray,
    range0_m: ndarray,
    slope_m_per_m: ndarray,
    h0_m: float,
)

    Slant range of one date on the reference grid, on a coarse lattice.

    rows / cols are the lattice pixel coordinates (float64, increasing); range0_m the zero-Doppler slant range [m] from the date's orbit to the ground point of each lattice node at the height h0_m; slope_m_per_m its derivative with respect to the target height [m per m]. For the grid (reference) date range0_m is the pixel's own slant range and the slope is zero.

    range_model ¶

    range_model(
    orbit_grid: Orbit,
    orbit_date: Orbit | None,
    az_time_s: Any,
    slant_range_m: Any,
    rows: Any,
    cols: Any,
    *,
    h0_m: float = 0.0,
    dh_m: float = 200.0,
    side: str = "right",
    doppler_grid: Any | None = None,
    doppler_date: Any | None = None,
    wavelength_m: float | None = None,
) -> RangeModel

    The :class:RangeModel of one date.

    orbit_grid is the orbit the image grid belongs to (the coregistration reference); orbit_date the orbit of the date (None = the grid date itself). az_time_s (nr values, seconds after orbit_grid.epoch) and slant_range_m (nc values, metres) are the azimuth time and slant range of the lattice rows / cols [px] on the grid. h0_m and dh_m [m] set the two ellipsoidal heights of the expansion.

    doppler_grid / doppler_date (the stripmap chain): the Doppler centroid polynomials [Hz of slant range] of the grid and of the date for products in native (squinted) geometry - the grid's goes into rdr2geo, the date's into geo2rdr, so the range difference is the one between the two squinted lines of sight, the phase a coregistered squinted pair carries (ISCE2 stripmapApp: geo2rdr with the secondary's Doppler, resamp_slc flattening with its range offsets). Both need wavelength_m [m]; None is zero-Doppler and leaves the model of v0.2.0–v0.3.0 unchanged.

    Units: seconds, metres and pixels in; metres and m/m in the model.

    simulated_phase ¶

    simulated_phase(

    Unwrapping¶

    bosar.core.unwrap ¶

    Phase unwrapping backends (ARCHITECTURE §6.5): SNAPHU binary, snaphu-py, scikit-image.

    The discovery of the binary/package is the caller's job (preflight.checks_binaries; the Step passes exe); this module works on in-memory arrays and an explicit backend. SNAPHU raw I/O: float32 in native byte order, INFILEFORMAT FLOAT_DATA (wrapped phase in radians), CORRFILEFORMAT FLOAT_DATA (coherence 0..1), OUTFILEFORMAT FLOAT_DATA (unwrapped radians), connected components UCHAR. The config/raw-file adapter follows the idea of snaphu-py (isce-framework, BSD-3 / Apache-2.0); nothing was copied. scikit-image's unwrap_phase (Herráez et al. 2002, BSD-3) is the licence-free fallback.

    COMPONENT_MODES module-attribute ¶

    COMPONENT_MODES = ('tile', 'regrow', 'reoptimize')

    How a tiled SNAPHU run labels connected components:

    • tile — SNAPHU's tile-mode assembly: components are grown per tile and renumbered by size; a region is never merged across a tile border (a coherent ramp over 2 x 2 tiles = 4 labels).
    • regrow — a second SNAPHU invocation on the tiled result with UNWRAPPED_IN TRUE and REGROWCONNCOMPS TRUE: the components are grown once over the whole image from the unwrapped phase and the same costs (no optimisation), so labels are full-image.
    • reoptimize — SNAPHU's SINGLETILEREOPTIMIZE TRUE: the tiled solution initialises a second, single-tile optimisation of the whole image, whose components are full-image. With one tile all three are the same run.

    Geometry and geocoding¶

    bosar.core.geometry ¶

    Range–Doppler geometry: rdr2geo and geo2rdr on the WGS84 ellipsoid.

    Zero-Doppler convention (Sentinel-1 TOPS/IW products are deskewed to zero Doppler): a target X imaged at azimuth time t and slant range R satisfies

    • (X − S(t)) · V(t) = 0 (zero Doppler: the line of sight is normal to the velocity)
    • |X − S(t)| = R (range sphere)
    • X on the ellipsoid inflated by the target height h: x²/(a+h)² + y²/(a+h)² + z²/(b+h)² = 1 (the usual approximation for h ≪ a; sub-millimetre for the round trip, and the DEM height is then the ellipsoidal height of the target).

    rdr2geo solves the three equations with Newton's method in ECEF (vectorised 3 × 3 solves), starting from a spherical-Earth guess on the requested side; geo2rdr solves the Doppler equation for t with Newton and reads R off the distance. Both are xp-agnostic and tiled by the caller (arrays of any shape). Units: seconds, metres, radians inside; degrees only in the lat/lon outputs, as the product layers store them.

    Doppler centroid (the stripmap chain): a product focused in its native (squinted) geometry - ALOS-1 PALSAR L1.1 - places a target at the azimuth time where the line of sight carries the Doppler centroid f_dc(R) [Hz], not where it is normal to the velocity. Both kernels take doppler (f_dc as a function of slant range: a callable or a polynomial object with r0_m / coeffs, as bosar.data.stripmap.DopplerPolynomial) and wavelength_m; the azimuth equation becomes

    2 (V · (X − S)) / (λ |X − S|) = f_dc(R)        (zero-Doppler: f_dc = 0)

    Sign. X − S points from the sensor to the target, so f_dc > 0 means the target lies ahead of the zero-Doppler plane (the beam squints forward, the sensor closes in: a positive Doppler shift). This is ISCE2 zerodop/geo2rdr (fn = dot(dr, satv) − 0.5 wvl f_dc(r) r, dr = xyz − satx) with the sign of its Doppler polynomial (dopplerVsPixel from the sensor readers, Hz), and zerodop/topozero (dopfact = 0.5 wvl f_dc r / |v| as the along-track component of the line of sight). doppler=None or an all-zero polynomial is the zero-Doppler code path of v0.2.0–v0.3.0, bit for bit.

    References: Curlander & McDonough (1991) §8; ISCE2 geometryLib (Apache-2.0; re-implemented).

    bosar.core.sbas.invert ¶

    SBAS network inversion.

    Small-baseline inversion after Berardino, Fornaro, Lanari & Sansosti (2002, IEEE TGRS 40(11)): the unknowns are the mean phase velocities of the N - 1 intervals between consecutive acquisitions; the unwrapped phase of the pair (i, j) (dates i < j) is the sum of v_k Δt_k over the intervals it spans. With per-pixel pair masks and weights the normal equations (Aᵀ W A) v = Aᵀ W d are solved for every pixel at once through a batched eigen-decomposition; eigenvalues at the noise floor are dropped, which is the minimum-norm (SVD) solution when the pixel's network splits into subsets (the velocity of an unobserved interval is then zero, Berardino's behaviour).

    Conventions (core/conventions.py): every interferogram is earlier * conj(later); its unwrapped phase is positive for a range increase, so the LOS displacement toward the sensor is -λ φ / (4π). Everything here stays in radians and years; :func:phase_to_los_m converts at the end. Temporal baselines are integer days, converted with 365.25 d/yr.

    Weights: the phase variance of a multilooked interferogram implied by its coherence γ and the number of looks L (Cramér-Rao bound, Rodriguez & Martin 1992): σ² = (1 - γ²) / (2 L γ²).

    Temporal coherence (Pepe & Lanari 2006): |Σ_p exp(j (d_p - (A v)_p))| / P over the pairs used at the pixel - 1 for a network that closes, low where unwrapping errors remain.

    DEM error (Fattahi & Amelung 2013, IEEE TGRS 51(7)): estimated in the time-series domain from the correlation of the displacement history with the perpendicular-baseline history, jointly with a polynomial deformation model.

    All kernels take the array module xp (NumPy or CuPy).

    bosar.core.sbas.unwrap_correct ¶

    Unwrapping-error correction by phase closure.

    Re-implemented from the paper: Yunjun, Fattahi & Amelung (2019), "Small baseline InSAR time series analysis: Unwrapping error correction and noise reduction", Computers & Geosciences 133, section 3.2 ("phase closure" method). MintPy's unwrap_error_phase_closure is GPL and was not copied.

    For one pixel let u be the unwrapped phases of the P pairs, C the n_tri x P triplet matrix (+1 for the pairs (i, j) and (j, k), -1 for (i, k)) and w the wrapped closure phases. The integer closure T = round((C u - w) / 2π) is zero for a consistent stack; an unwrapping error of U_p cycles in pair p shows up in every triplet of that pair. The correction is the integer vector U that minimises the L1 norm of the misfit |C U + T|_1 (with the fewest corrections among equal misfits); the corrected phase is u + 2π U.

    Millions of pixels share few distinct closure vectors T (most are all zero), so the problem is solved once per unique closure pattern:

    1. the minimum-norm start: U0 = round(-C⁺ T) with the pseudo-inverse of the (masked) closure matrix - the solution orthogonal to the null space of C, i.e. with the per-date gauge fixed and U = 0 by construction on every pair that sits in no triplet; it is accepted only when it closes every triplet exactly and is sparse (at most 3 corrected pairs, or 10 % of the pairs), the sparse answer being the assumption of the method;
    2. everything else goes to the exact L1 linear program (HiGHS), run in a process pool under a time budget in the order of the pixels a pattern covers; a pattern the budget does not reach is left uncorrected and counted;
    3. a correction that does not close its triplets exactly is never applied.

    The closure constrains U only up to integer combinations of per-date cycles (adding n_j - n_i to every pair changes no triplet), and a pair in no triplet is not constrained at all: the minimum-norm choice assumes that few interferograms are wrong, which is the assumption of the method.

    bosar.core.iono ¶

    Ionospheric phase by the range split-spectrum method.

    The ionosphere advances the phase by an amount proportional to 1 / f (dispersive); geometry, deformation and troposphere delay it in proportion to f (non-dispersive). An interferogram made from the lower and one from the upper part of the range spectrum (centre frequencies f_L, f_H) separate the two (Gomba et al. 2016, "Toward operational compensation of ionospheric effects in SAR interferograms: the split-spectrum method", IEEE TGRS 54(3), eqs. 5-6; Brcic et al. 2010):

    phi_iono(f0)    = f_L f_H / (f0 (f_H^2 - f_L^2)) * (phi_L f_H - phi_H f_L)
phi_nondisp(f0) = f0 / (f_H^2 - f_L^2) * (phi_H f_H - phi_L f_L)

    with phi_L, phi_H the unwrapped sub-band phases. The sub-bands differ from the full-band phase by about phi * (f_c / f0) (a few hundredths of a radian per cycle), so only the full band is unwrapped: with d = arg(I_H conj(I_L)) the sub-band phases are phi_unw -+ d / 2 (the full band sits midway) - no second unwrapping, no 2 pi ambiguity between the sub-bands, and the estimate stays unbiased in noisy cells (tested at coherence 0.4). What the method cannot see is a phase that is flat in frequency: a constant, or the 2 pi k between regions unwrapped independently, reads as half its value.

    The input must be flattened. Coregistration moves the secondary's envelope by the modelled range difference but leaves the full-band carrier phase 4 pi dR / lambda0 in both sub-bands (a sub-band radar would have seen 4 pi dR / lambda_sub). Removing the modelled geometric phase from all three interferograms (slc_flatten, same orbits and DEM as the coregistration) takes that term out identically; what remains - troposphere, deformation, orbit residuals, ionosphere - is a true, uncompensated delay or advance and carries the proper frequency dependence. Without flattening half the geometric phase would be read as ionosphere.

    The estimate amplifies phase noise by about f0 / (f_H - f_L) (some 170 for Sentinel-1 IW): it is made on heavily multilooked interferograms and low-pass filtered with coherence weights (:func:lowpass_weighted); the ionosphere is smooth at the scales that survive.

    Connected components. Regions unwrapped independently (SNAPHU connected components, or the separate regions scikit-image unwraps on a masked grid) differ by an unknown 2 pi k of full-band phase. Both sub-band phases inherit it, so the dispersive phase of such a region is off by k times :func:ambiguity_step_rad = 2 pi f_L f_H / (f0 (f_L + f_H)) (pi (1 - f_c^2 / f0^2), i.e. pi to 7 ppm for Sentinel-1). :func:component_constants removes each component's weighted median before the low-pass; :func:closure_residual and :func:plane_fit_components are the validation tools that are blind to those constants; :func:predicted_raw_std and :func:lowpass_noise_std predict the estimator's noise from the coherence and the looks.

    Units: Hz, radians. Pure array code on xp; no I/O. Re-implemented from the papers.

    bosar.core.ccd ¶

    Coherence change detection (SPEC §3.2 C): coherence loss between pre-event and co-event pairs, its z-score against the pre-event pair-to-pair variability, and the damage proxy map.

    Definitions (all on one multilooked grid; xp = NumPy or CuPy):

    bosar.core.amplitude ¶

    Relative amplitude change on coregistered stacks (SPEC §3.2 F) — pure xp.

    On the GAMMA/StaMPS export the SLCs are not radiometrically calibrated: amplitudes are compared relative to each other after a per-date normalisation that removes gain differences between acquisitions.     bosar.core.offsets ¶

    Offset tracking: normalised cross-correlation (NCC) of oversampled amplitude patches.

    What is measured. For every patch of a regular grid, the 2-D shift between a reference and a secondary image (amplitude only; the interferometric phase is not used), with the NCC peak, a signal-to-noise ratio and an outlier mask. Pure xp (NumPy or CuPy): the patches of a chunk go through one batched FFT, so the GPU path is the same code.

    Sign convention (binding; docs/design/offsets.md §3). The offset is the position of a feature in the secondary minus its position in the reference, in (azimuth line, range sample) pixels: sec(r + d_az, c + d_rg) ≈ ref(r, c). Positive range = towards increasing slant range (a range increase, i.e. motion away from the sensor, so the LOS displacement of ARCHITECTURE §5, positive toward the sensor, is −offset_range_m); positive azimuth = towards increasing line number. :func:fourier_shift with a positive shift moves the content towards increasing indices, so a secondary built with it reads that shift back.

    Algorithm (ampcor, ISCE2 components/mroipac/ampcor and contrib/PyCuAmpcor, Apache-2.0; read for the method, re-implemented in xp, no code copied):

    1. Complex patches are demodulated (:func:deramp), oversampled oversample times by FFT zero padding (:func:oversample) and only then detected (|.|). The amplitude of a complex signal has twice its bandwidth: detected at the original sampling it is aliased and the correlation peak locks to whole pixels (as 0.31 px from complex-domain oversampling). The demodulation matters for Sentinel-1 TOPS: the azimuth spectrum of a patch sweeps about 3.5 Hz per line (≈ 230 Hz over 64 lines) on top of the 327 Hz bandwidth, more than the 486 Hz PRF; local removes the per-row instantaneous frequency (lag-one correlation along azimuth, smoothed over a few rows, integrated), which also follows the Doppler jump at a burst seam. Real (amplitude) input is oversampled as it is.
    2. The mean-removed reference amplitude is correlated with the secondary search window at every lag of the oversampled grid by FFT; the NCC denominator comes from summed-area tables of the secondary (float64).
    3. Integer peak; edge when it lies less than 1 px from the border of the search area. SNR = peak² / mean(ρ²) over the search surface outside a (2e + 1)² exclusion box around the peak (ampcor: peak² over the mean ρ² around the peak; the box keeps the main lobe out).
    4. Sub-pixel: the NCC surface around the peak is interpolated with a Hann-tapered sinc on a grid corr_oversample times finer over ±1 sample, the maximum refined by a parabola. Near the search border the kernel narrows symmetrically instead of being cut on one side.
    5. :func:outlier_mask: SNR below snr_min, the peak on the search edge, or a deviation from the 3 × 3 median of the offset field above mad_k times the field's MAD.

    Units: pixels for every offset, size and position; metres only through :func:offsets_m.

    bosar.core.speckle ¶

    Speckle filters on SAR intensity - pure xp.

    Every filter works on intensity (power: |z|^2 or a calibrated backscatter coefficient, linear, float32) under the multiplicative model I = R * n with E[n] = 1 and var(n) = 1 / L; L is the equivalent number of looks (ENL) of the intensity and Cu = 1/sqrt(L) the coefficient of variation of pure speckle. The filters:

    • boxcar: the mean over a w x w window;
    • lee (Lee 1980): R = m + b (I - m), b = var_R / (m^2 Cu^2 + var_R), var_R = (var_I - m^2 Cu^2) / (1 + Cu^2), local mean m and variance var_I;
    • refined_lee (Lee 1981; Lee, Grunes & De Grandi 1999): the edge direction from the 3 x 3 sub-means of the window (four gradient masks), then the Lee estimate over the one of eight directional, non-square half windows (with the edge line) on the side of the centre;
    • frost (Frost et al. 1982): R = sum(m_k I_k) / sum(m_k), m_k = exp(-K Ci^2 d_k) with the damping factor K, the local Ci^2 = var_I / m^2 at the centre and d_k the distance [px];
    • gamma_map (Lopes, Nezry, Touzi & Laur 1990): the MAP estimate under a Gamma-distributed scene; Ci <= Cu: the mean, Ci >= Cmax (default sqrt(2) Cu): the pixel itself;
    • nlmeans (Buades, Coll & Morel 2005; the patch similarity of Deledalle, Denis & Tupin 2009): weighted mean over a search window; the weight of a candidate decreases with the generalised likelihood ratio of two Gamma-distributed patches, d = L log((a + b)^2 / (4 a b)) per pixel pair, averaged over the patch, minus its expectation under "same reflectivity".

    No-data: NaN and non-positive pixels keep their value and never enter a neighbour's statistics (every local sum runs over the valid pixels only). The output at a pixel depends on the input within :func:speckle_halo pixels; every kernel pads its block symmetrically (scipy's reflect) so a core.tiling.Tiler with that halo (clipped at the image edge) reproduces the whole-image result. The ENL is a scalar input: estimate it once on the whole image (:func:estimate_enl) and pass it to every tile. Local sums are direct (correlate1d), not running sums, and accumulate in float64: a bright point target on a line does not leave rounding residue in a dark neighbour's variance.

    lee(
    intensity: Any,
    xp: ModuleType,
    *,
    enl: float,

    Lee (1980) local-statistics filter for multiplicative speckle; float32.

    R = m + b (I - m), b = var_R / (m^2 / L + var_R) (Lee 1980, the gain of the linearised model I ~ R + m (n - 1)), var_R = max(var_I - m^2 / L, 0) / (1 + 1/L); m, var_I over the valid pixels of the window. b is 0 on homogeneous areas and tends to 1 on edges and point targets (the exact MMSE gain var_R / var_I of Kuan and of the refined Lee stops at 1 / (1 + 1/L), half the pixel at one look).     refined_lee ¶

    refined_lee(
    intensity: Any,
    xp: ModuleType,
    *,
    enl: float,
    window_px: int = DEFAULT_WINDOW_PX,
) -> Any

    Refined Lee filter (Lee 1981; Lee, Grunes & De Grandi 1999); float32.

    In the w x w window (7 in the paper) the 3 x 3 sub-means (3 x 3 pixels each, stride 2 at w = 7) give four gradients (horizontal, vertical, two diagonals); the strongest picks the edge direction, and the centre's side is the one whose outer sub-mean is closer to the centre sub-mean. The estimate m + b (I - m) of Lee et al. (1999), b = var_R / var_I, then uses the mean and variance of that directional window (one of eight half windows with the edge line, 28 pixels at w = 7). Units: intensity (power, linear) in and out; enl dimensionless; window in pixels (>= 5).

    frost(
    intensity: Any,
    xp: ModuleType,
    *,
    window_px: int = DEFAULT_WINDOW_PX,
    damping: float = DEFAULT_DAMPING,
) -> Any

    Frost et al. (1982) adaptive exponential kernel; float32.

    R = sum_k m_k I_k / sum_k m_k over the valid pixels of the window, m_k = exp(-K Ci^2 d_k) with K = damping, Ci^2 = var_I / m^2 the local squared coefficient of variation at the centre and d_k the Euclidean distance to the centre.     gamma_map ¶

    gamma_map(
    intensity: Any,
    xp: ModuleType,
    *,
    enl: float,
    window_px: int = DEFAULT_WINDOW_PX,
    cmax: float | None = None,
) -> Any

    Gamma-MAP filter (Lopes, Nezry, Touzi & Laur 1990); float32.

    With Cu = 1/sqrt(L), Ci = sqrt(var_I) / m and alpha = (1 + Cu^2) / (Ci^2 - Cu^2): Ci <= Cu: R = m (homogeneous); Ci >= Cmax: R = I (point target); otherwise R = ((alpha - L - 1) m + sqrt(m^2 (alpha - L - 1)^2 + 4 alpha L I m)) / (2 alpha). cmax default sqrt(2) Cu (Lopes, Touzi & Nezry 1990).     glr_h0_mean ¶

    glr_h0_mean(enl: float) -> float

    Expected per-pixel GLR dissimilarity L log((a + b)^2 / (4 a b)) of two independent L-look intensities of the same reflectivity: L (2 psi(2L) - 2 psi(L) - 2 log 2) (0.614 at L = 1, -> 0.5 for large L).

    Units: dimensionless; enl in looks.

    nlmeans ¶

    nlmeans(
    intensity: Any,
    xp: ModuleType,
    *,
    enl: float,
    window_px: int = DEFAULT_WINDOW_PX,
    patch_px: int = DEFAULT_PATCH_PX,
    h: float = DEFAULT_H,
) -> Any

    Non-local means for Gamma-distributed intensity; float32.

    Every pixel q of the window_px x window_px search window around p gets the weight exp(-max(D(p, q) - mu0, 0) / h): D is the mean over the patch_px x patch_px patches of the generalised likelihood ratio of two L-look intensities (Deledalle, Denis & Tupin 2009), d(a, b) = L log((a + b)^2 / (4 a b)) (scale-invariant, >= 0, 0 for a = b), and mu0 its expectation for equal reflectivities (:func:glr_h0_mean), so h is the tolerated excess dissimilarity. The centre pixel has D = 0 and weight 1, the largest possible: with mu0 subtracted, neighbours of the same reflectivity weigh close to 1 too (Buades et al. 2005 replace the centre weight by the largest neighbour weight, which flattens point targets further). An isolated point target is one pixel of the patch_px^2 in its patch, so it is kept only when L log(ratio) / patch_px^2 exceeds h clearly: at 4 looks a 26 dB target keeps about half of its intensity (-3 dB), at one look a 30 dB target loses about 11 dB (3 x 3 patch, h = 0.5; tests/test_speckle.py measures it). R = sum w_q I_q / sum w_q; averaging intensity (not log-intensity) keeps the mean. Units: intensity (power, linear) in and out; enl, h dimensionless; windows in pixels.

    estimate_enl ¶

    estimate_enl(
    intensity: Any,
    xp: ModuleType,
    *,
    block_px: int = 32,
    fraction: float = 0.1,
    min_blocks: int = 4,
    min_valid: float = 0.9,
) -> EnlEstimate

    Automatic ENL from the most homogeneous blocks of the image.

    The image is cut into block_px square blocks (at least min_valid of their pixels valid). Each block's pixels are split like a chessboard: the squared coefficient of variation CV^2 of the even half ranks the blocks, the fraction with the lowest (at least min_blocks) are kept, and ENL = 1 / mean(CV^2) of the odd half of those blocks. Ranking and estimating on disjoint pixels removes the selection bias of "the block of lowest CV" (on uncorrelated speckle the estimate is unbiased; textured blocks rank last). window is the block of lowest CV.     bosar.core.tiling ¶

    Tiled processing of rasters that never assumes an image fits in memory.

    Tiler partitions an image into write windows (each pixel written exactly once) and gives each tile a read window enlarged by a halo that is clipped at the true image edge. Kernels that use mode="reflect" therefore see the real edge on boundary tiles and real neighbours elsewhere, so a tiled uniform_filter equals the untiled result as long as halo >= size // 2.

    Design follows dolphin's io/_blocks.py (isce-framework, Apache-2.0/BSD-3): block indices, padding and trimming; re-implemented, no code copied (THIRD_PARTY_NOTICES.md: reference only). All coordinates are integer pixels, half-open [start, stop); the pixel centre is the index.

    bosar.core.conventions ¶

    Binding numerical conventions (docs/ARCHITECTURE.md §5, the project rules) as constants and helpers.

    Every kernel imports these instead of re-deriving 4π/λ locally. Units are SI: metres, seconds, radians; temporal baselines are integer days and become years only here (DAYS_PER_YEAR).
